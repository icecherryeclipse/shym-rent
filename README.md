### 2. Описание проекта
Проект представляет собой контейнеризированное веб-приложение для анализа данных проката лыжного инвентаря (Вариант 1). 
Состоит из двух сервисов, объединенных через Docker Network (`shym-net`):
1. **API-сервер** (Python/Alpine) — обрабатывает CSV-данные, прогоняет юнит-тесты при многоэтапной сборке и отдает JSON-отчет.
2. **Web-сервер** (Nginx) — раздает статический HTML/JS дашборд и проксирует запросы к API.

### 3. Как запустить проект локально
```bash
docker network create shym-net
docker container run -d --name shym-api --network shym-net shym-rent:v3
docker container run -d --name shym-web -p 8501:80 --network shym-net -v $(pwd)/web:/usr/share/nginx/html:ro -v $(pwd)/web/nginx.conf:/etc/nginx/conf.d/default.conf:ro nginx:alpine

После запуска интерфейс будет доступен по адресу: http://localhost:8501

```
### 4. Ответ на теоретический вопрос

*Вопрос:* Если мы временно изменим одну строку в records.csv, какие шаги сборки Dockerfile выполнятся заново, а какие возьмутся из кэша?

*Ответ:*
При изменении файла records.csv инвалидируется кэш слоя COPY data/ data/. Следовательно, Docker возьмет из кэша только базовый образ (FROM ...) и копирование папки tools/.
Все последующие шаги будут выполнены заново:
    1.Запуск скрипта генерации отчета (RUN python tools/build_report.py).
    2.Копирование тестов и их запуск на стадии test.
    3.Финальное копирование обновленного report.json в чистый образ.
    Это гарантирует, что измененные данные обязательно пройдут валидацию тестами перед созданием финального образа.
